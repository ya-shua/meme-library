# meme-library 对接说明

机器可读的部分在仓库根 `metadata.json`（`capabilities` / `standalone` / `contract`）；本文档讲人怎么接。

## 定位

本地表情包收录库 + 自带 aiohttp 大厅（默认 `127.0.0.1:7802`）。图自己管（`memes/`），库自己管（`data/meme_library.db`），
不依赖任何框架；**只有聊天指令那一层**需要宿主（海螺）提供 `core.message` 与 `ctx`。

## 三种接法

1. **当海螺插件挂（全功能，推荐）**
   目录放进宿主 `plugin_paths`，宿主调 `main.py:setup(ctx)` / `teardown(ctx)`。
   用到宿主的：`core.message`（`Segment` / `make_text`）、`ctx.config`、`ctx.services`、`ctx.on`、`ctx.log`、`ctx.send`。
   会包装 `ctx.services["stickers"]` —— 自动配图走本图库，失败回退原服务；运行时对象放在 `ctx.services["meme_library"]`。

2. **只接 HTTP 大厅（进程内嵌或独立进程）**
   自己装配 `HallServer(plugin_root, db, downloader, tagging, vision, preview=None)` 再 `await start(host, port)`，
   之后 `/api/*` 全可用，前端就是 `/`。装配细节见下面「单独运行」。

3. **只用文件与数据库（不起进程）**
   `data/meme_library.db`（SQLite）里的 `packs / images / image_tags / mood_mappings`，图片在 `memes/<集合名>/`。
   只读查询不需要 aiohttp，也不需要跑服务。

## 能力清单

`GET /api/manifest` → `metadata.capabilities`（6 条），各自对应的接口：

| 能力 | 入口 |
|---|---|
| 本地表情包收录库 | `/api/packs`、`/api/images`、`/api/img` |
| Git 仓库下载入库 | `POST /api/download`、`/api/download/status|tasks` |
| 大厅预览与集合隔离 | `/api/repo/inspect`、`/api/store/*`、`POST /api/packs/enable` |
| 两档审核（高置信/待审核） | `POST /api/review/confirm|batch|revert` |
| 心情映射自动配图 | `/api/moods`、`/api/tag/counts`、`services["stickers"]` 桥接 |
| 梗图独立不自动发 | `PACK_MEME`，只走手动 `/梗图` |

标准分类与包类型：`GET /api/constants`。对话指令：`/meme`、`/梗图`、`/下载`、`/启用`、`/列表`、`/状态`、`/本地`、`/识别`、`/入库`。

## 契约端点（只读）

### `GET /api/health`

```json
{"ok": true, "id": "meme-library", "version": "1.1.1", "uptime_s": 6}
```

- `id` 取自 `metadata.json` 的 `id`（读不到就是空串）
- `version` 取**代码常量** `meme_core/constants.py:PLUGIN_VERSION`
- `uptime_s` 从 `HallServer` 构造（`self.started_at`）算到本次请求

### `GET /api/manifest`

```json
{
  "ok": true,
  "metadata": { "id": "meme-library", "version": "1.1.1", "capabilities": ["…"], "standalone": {"…": "…"}, "contract": "docs/对接.md", "…": "…" },
  "runtime": { "port": 7802, "pid": 33252, "started_at": "2026-11-09T23:30:26+08:00" }
}
```

- `metadata` 是**仓库根 `metadata.json` 原文**（不改写、不裁剪）
- `runtime.port` 是**实际监听端口**（宿主改过 `config.json` 的 `hall_port` 时，它跟 `metadata.port` 会不一样）
- `started_at` 是带本地时区偏移的 ISO 8601

两个端点都不带密钥、用户名、绝对路径、图片/集合清单内容。

**版本一致性**：`metadata.json:version` 是副本，必须与 `PLUGIN_VERSION` 手动保持一致；
两者不一致时以**代码常量**为准（`/api/health` 报的就是它）。

## 失败语义

| 情况 | 表现 | 宿主该怎么办 |
|---|---|---|
| 端口被占 | `start()` 抛 `OSError`，`setup()` 失败 | 换 `hall_port` 或先停旧实例 |
| `metadata.json` 缺失/坏 | 契约端点**不 500**：`id` 为空串、`metadata` 为 `{}`，`ok` 仍 `true` | 「活着」与「元数据坏了」分开判断 |
| 数据库打不开 | 既有接口 500，`/api/health` 仍 200 | 健康检查只反映进程与运行期元数据，不代表业务可用 |
| 用 POST 访问契约端点 | 405（只注册了 GET） | — |
| 公网暴露 | 无任何鉴权（含写接口） | 只听 127.0.0.1，别转发出去 |

## 单独运行

依赖只有 aiohttp（`pip install -r requirements.txt`；Pillow 可选，装了缩略图更快）。
在**这个仓库目录下**运行（`meme_core` / `server` 是可导入的包）：

```python
# hall_alone.py —— 只要大厅，不要聊天指令
import asyncio, pathlib
from meme_core.database import Database
from meme_core.downloader import GitDownloader
from meme_core.tagging import TaggingService
from server.hall_server import HallServer

async def main():
    root = pathlib.Path(__file__).resolve().parent
    db = Database(str(root / "data" / "meme_library.db"))
    hall = HallServer(
        plugin_root=root, db=db,
        downloader=GitDownloader(root, db, root / "data" / "temp"),
        tagging=TaggingService(root, db),
        vision=None,              # AI 打标要视觉模型，留空则只有本地推断
    )
    await hall.start("127.0.0.1", 7802)
    await asyncio.Event().wait()

asyncio.run(main())
```

## 自检 curl

```bash
curl -s http://127.0.0.1:7802/api/health
curl -s http://127.0.0.1:7802/api/manifest
```

合格的标志：两条都是合法 JSON 且 `"ok": true`；`health.version` 与 `metadata.json` 的 `version` 一致；
`manifest.runtime.port` 等于你监听的那个端口。
